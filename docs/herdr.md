# Herdr

`files/home/.config/herdr/config.toml` owns the permanent UI, keybindings, and
sidebar settings. Mise copies it into `~/.config/herdr/config.toml` during
`dotf run`.

## Local plugin registration

`config/config.yml` declares local plugin source directories in `herdr_plugins`.
The Herdr plugins Step runs `herdr plugin link --enabled PATH` for each available
manifest on every convergence. Re-linking refreshes registration from the current
manifest and restores the enabled state without replacing unrelated registrations.

`~/.config/herdr/plugins.json` is **generated by Herdr**, not a dotfiles source.
It contains resolved manifest metadata and absolute checkout paths; do not copy it
into git or edit it to change a plugin. Change the source manifest instead.
Missing Herdr or missing local checkouts are reported as notices and skipped, so
other machines can still converge. Once restored, run `dotf run` again.

The `speedshop.workspace-prefix` plugin implementation remains in
`client_notes/agent_tooling/herdr-workspace-prefix`. The space synchronization
manifest and tooling also remain in `client_notes/agent_tooling/herdr-sync`; they
are not machine-wide dotfiles.

## Pi status

The existing `files/home/.pi/agent/extensions/herdr-status/{index.ts,reporter.ts}`
extension is already managed by the home-tree copy. It reports Pi workflow state
to Herdr, including background work. The legacy `herdr-agent-state.ts` extension
remains disabled in Pi settings.

Herdr runtime sessions, logs, sockets, and plugin command output are not managed
or checked into this repository.
